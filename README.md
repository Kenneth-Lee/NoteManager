# NoteManager

## 一句话介绍

NoteManager是一个意在取代类似Obsidiant那样的笔记管理工具的开源软件。

## 初始设想

我大部分时间用Python-Sphinx写我的笔记，在一些项目里，偶尔也会用markdown。Sphinx
的好处是格式完整，比较适合写书，缺点是要考虑这是哪个主题的一部分，要多写不少额
外的东西，关键是要看之前，还要编译一下，内容多了以后编译时间很长；Markdown的好
处是简单快捷，适合临时写个笔记，不用考虑写的这个东西具体属于哪个章节，缺点是章
节之间互相独立，除了用grep查找，没有更好的查找方法。

我也尝试过用Obsidian一类的工具去自动管理这些关联关系，但我还是觉得不好用，
Obsidian那些关联图看着很Cool，其实对于检索内容没啥用。我更希望是：打开界面，在
搜索框中随便找一个关键字，然后我选择某个文档，直接看就行。在那个文档中如果访问
内部链接，也能访问。文档中也可以索引某个关键字，可以通过那个关键字找出我要的一
个或者多个文档，我同样可以跳过去。这样就方便多了。而且我觉得我也不想绑定某种格
式，我可以同时支持rst和md文件，把原来的rst和md文件直接拷贝进来，你原来就是个
sphinx项目或者obsident项目也行。我都不管，我把里面的md和rst文件全部纳入管理，生
成我的数据库和html渲染，这样你那头编辑你的，我这头给你生成索引，你打开html看就
行了。

我的整体思路是：把你要管理的所有工作都放同一个目录下，我在这个目录下创建一个
.NoteManager子目录，在里面给你生成索引和html文件。然后动态监控你的修改，有文件
被修改了（包括被增加了），我就更新索引。我们尽量不使用Sphinx那样的一次次重新生
成静态索引的机制，每个rst文件我都看作是独立的，里面有一组可以被别人索引的引用，
都可以作为被搜索的对象，而其他文件，要不直接链接这个文件的某个位置，要不请求动
态索引，我直接根据关键字动态计算是什么页面的什么位置，直接给你找出来。

这样做有个缺点是：如果你有多个NoteManager项目怎么办？一种方法是统一管理，为所有
的项目都建立统一的索引系统。但用户要把这些项目分开，总有他的道理，所以我最终的
想法是让一个后台监控多个目录。如果你就一个项目，那一切都好，如果你有不止一个项
目，你可以指定项目处理，也可以给一个全局的搜索要求，我们一个个来查找。我尽量让
你在电脑上自动完成所有的索引建立工作，然后每个项目里面的html文件里面，就带了所
有的索引和查找需要的脚本，这样你直接把这个html目录，随便拷贝到什么地方去，都可
以直接阅读。

我还写了一个手机软件：
[本地管家](https://atomgit.com/Kenneth-Lee-2025/local_manager)，
支持把html目录压缩成zip文件，可以在手机上直接查看。

所以，在一个单机上，我希望从一个接口上可以维护所有的项目，可以尽快查找，编辑，
查看写好的笔记，希望有尽量多的关联管理，有更多的索引可以查找对应的笔记。而在分
享上，我希望对每个项目生成的html可以单独打包，打包的内容保持这个项目中的所有索
引查找功能。

## 软件架构

为了实现软件的长远发展，我们维护几个核心逻辑：

第一，软件是针对某个用户的，而不是针对某个项目的，所以，全局的配置都在用户的
.NoteManager目录下，你配置了多少项目，项目的位置在哪里，都在这一层管理。你可以
在项目的目录中发出命令，这个命令也可以认知当前你在管理这个项目，但不影响命令总
是全局地看到所有的信息。

为此，我们采用一个后台服务加前端命令的模式。后台服务也不需要用户管理，用户命令
发出的时候，如果后台服务没有启动，由用户命令主动拉起后台服务即可。用户命令的最
终处理，都在后台服务完成，所以，始终是一个独立的实体在维护所有的目录。

我们后面把用户命令称为notemanager，或者简称nmr，把后台服务称为
notemanager-daemon，或者简称nmrd。

第二，nmrd维护每个项目目录，我们尽量不管你里面有什么内容，我们就是把所有的目录
中的.md或者.rst纳入管理，不介入你的其他管理，然后持续把里面的内容加入到我们的索
引服务中。nmrd只根据你的内容更新项目中的.NoteManager目录，和这个项目有关的信息，
都更新在这里，这样你喜欢怎么管理这个目录nmrd都不影响。你这个目录作为sphinx工程
维护也行，作为Obsidian工程维护也行，这都不影响你用nmrd来建立索引，并直接查看里
面的内容。

第三，为了提供一个通用的图形界面，我们通过nmrd开启一个webui接口。让你可以直接通
过浏览器维护项目，也可以直接查看每个独立项目的内容。我们把这个图形界面和你的命
令行结合起来：你可以在界面上创建，删除，管理项目，也可以在命令行上用nmr做一样的
操作。这两种请求都会发到nmrd后台上做相同的逻辑处理。

请注意，这里我们实际提供了两个webui：一个是我们这里提到的nmrd提供的webui，这个
webui总是可以发出全局的命令，也可以随时接受nmr后台发来的命令。另一个webui是我们
前面承诺的：对每个项目，我们都会生成一个html目录，哪里有我们通过动态监控工程的
变化，不断产生新的索引，最后用户单独打开那个目录，随便打开一个文件，都可以查找
其他文档。

所以，你通过nmrd的webui看到的是一个管理界面，在这个管理界面上，当你具体查看某个
项目，或者进入某个项目的界面，它通过内嵌的窗口显示那个项目的信息。

整个NoteManager的目的是快速定位我们要的笔记，我们从命令行和webui上，都提供这种
能力：我们在每个页面上都提供查找对话框，你输入部分关键字或者正则表达式，都可以
找到所有索引到的关键字。然后你就可以跳过去。在命令行上，你也可以用nmr search命
令去做一样的查找。

我们把这两者联动起来：如果你在命令运行查找命令，这个更新也会发到webui上，这样你
在命令行上查找某个内容，webui也同步更新，以便你可以直接找它。如果你在编辑某个md
文件，马上要在webui上看到它，你也可以直接运行nmr view xxx.md这样要求查看它，这个
请求同样会发到webui上，跳转到对应的渲染好的html上显示它。

甚至，即使这个md文件不在项目管理之内，我们也可以实时渲染出来，只是没有配套的其
他索引而已。

如果你像我一样喜欢使用命令行的编辑器，nmr也能最快帮你找到这个文件，你可以用nmr
searche命令做查找，这个命令的结果和search一样，但你可以选择一个搜索结果，然后编
辑它。对于命令行爱好者，这给你一个随时编辑笔记的机会，拿起来就用，记完就退出。

当然，希望vscode人也可以把EDITOR环境变量设置为code，用vscode来编辑你的文件。

这样我们就闭环了：你可以找一个目录写你的笔记，可以通过search或者searche找到这些
笔记进行编辑，可以用view来看它的内容……最后，你可以把这些笔记按目录打包进行分发。

我们尽量不做plugin系统。所谓plugin，本质上就是把你绑上我们的业务流，要求你的行
为是插在我们的业务流上的。我们提供的是服务，服务就是“你给我什么，我还你什么”。
如果你要找一个AI来总结你的你笔记，然后写在另一个目录中，或者做其他分类，你单独
做就行了，不需要和NoteManager的行为发生关联。

## 安装

```bash
pip install -e .
```

依赖：Python >= 3.10，自动安装 docutils、Markdown、pygments、watchdog。

## 使用

### 启动

```bash
notemanager start
```

Daemon 启动后自动开启 Web 控制面板，默认地址：http://localhost:19833

### 添加监控目录

```bash
notemanager add /path/to/your/notes
```

添加后自动执行首次构建并开始监控文件变化。

### 其他命令

```bash
notemanager status          # 查看 daemon 状态和所有项目信息
notemanager list            # 列出所有监控中的目录
notemanager remove <目录>   # 停止监控并删除生成的文件
notemanager stop            # 停止 daemon
```

### Web 控制面板

启动 daemon 后访问 http://localhost:19833 ，可以：

- 查看所有监控目录及其状态
- 添加/移除目录
- 手动触发重建
- 直接浏览各项目的 HTML 输出

### 可移植性

每个被管理的目录下会生成 `.NoteManager/` 子目录，其中的 `html/` 目录是完整的可浏览站点。将整个 `.NoteManager/` 拷贝到任何有浏览器的地方都能使用，包括搜索功能。

## 目录结构

被管理目录下的 `.NoteManager/`：

```
.NoteManager/
├── html/                   # 渲染后的 HTML，保持原目录结构
├── index/
│   ├── search_index.json   # 全文搜索索引
│   └── ref_labels.json     # 交叉引用标签映射
├── static/
│   ├── notemanager.css
│   └── notemanager.js
└── status.json
```

全局配置在 `~/.NoteManager/`：

```
~/.NoteManager/
├── config.json     # 监控目录列表和端口配置
├── daemon.json     # daemon 运行时信息（PID、端口）
└── daemon.log      # 后台日志
```
