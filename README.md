# NoteManager

## 一句话介绍

NoteManager是一个基于命令行和WebUI的，以个人充分掌控信息，不被任何商业盈利目的绑定的笔记管理软件.

## 初始设想

我大部分时间用Python-Sphinx写我的笔记，在一些项目里，偶尔也会用markdown。Sphinx的好处是格式完整，比较适合写书，缺点是要考虑这是哪个主题的一部分，要多写不少额外的东西，关键是要看之前，还要编译一下，内容多了以后编译时间很长；Markdown的好处是简单快捷，适合临时写个笔记，不用考虑写的这个东西具体属于哪个章节，缺点是章节之间互相独立，除了用grep查找，检索比较麻烦。

我也尝试过用Obsidian一类的工具去自动管理这些关联关系，但我还是觉得不好用，Obsidian那些关联图看着很Cool，其实对于检索内容没啥用。我更希望是：我输入一个关键字，自动帮我找到和这个关键字相关的文档，然后我开始编辑，编辑完了存盘，我就不用管了。我又不是编辑，信息记录进去就行了，其他的尽量我就不想介入。如果要处理这些信息，我也不打算提供插件，我的逻辑是：这不过是个数据库，你爱怎么处理它，你独立处理就是了，我的控制流和那个工具没有关系，这样你才具有所有的主动性。

对于这样一个需求，NoteManager的作用主要就是建立索引，我也不绑定特定的格式，我先支持txt, rst和md格式，以后还可以增加更多的文本格式。NoteManager的工作就是按约定把里面的索引找出来，建立一个索引数据库。而每个文本文件本身，按照格式的约定，都渲染成html文件。这样，一方面你可以通过索引数据库找到文档，另一方面你也可以同时看到文档和它渲染后的结果。这样，作为笔记，它该做的就都做了。其他功能，就不是笔记软件本身的功能了。

为此，我这里尽量不介入你的文件管理。你把你要管理的所有笔记都放同一个目录下，我在这个目录下创建一个.NoteManager子目录，在里面给你生成索引和html文件，不改变你任何内容，你不需要NoteManager了，你把这个目录删掉就是了。NoteManager后台可以动态监控你的修改，你用其他工具更新了目录中的笔记文件，我们就在后代给你动态更新索引。

所以，我们不使用Sphinx那样的一次次重新生成静态索引的机制。我们把每个笔记都看作是独立的，里面有一组可以被别人索引的引用，都可以作为被搜索的对象，而其他文件，要不直接链接这个文件的某个位置，要不请求动态索引，我直接根据关键字动态计算是什么页面的什么位置，直接给你找出来。其他文件搜索，除了支持原来rst/md等文件的静态索引，我们也支持动态索引语法。也就是说，如果你没有指定确切的位置，索引某个关键字，我们的搜索是一段搜索NoteManager索引数据库的代码，你总可以从最新的更新中找到对应的定义。

我们整个设想是一个用户的笔记，全部都在一个目录下，你分简单的目录建构以便拷贝就行了，其他随便放，反正最后我们都是通过索引找到它的。但用于有时会引入多个目录，以便实现不同的功能，比如有些目录是日常笔记，有些目录是某本Sphinx写的书。这样用户不会希望这两者的索引是在一起的，所以，我们还是有“Project（项目）”的概念，但我们不希望用户需要进入或者打开那个项目，然后才能控制那些笔记，因为用户的思路一闪即逝，笔记这种东西，还是尽快打开就开始记录，记录完了扔在那里，慢慢整理才好。所以，你可以创建很多项目，但其中有一个是默认项目，默认的操作都是在这个项目上，但你也可以立即指定项目进行查找或者修改。

这样我们就有两种控制目录：一种是针对项目的.NoteManager，另一种是针对用户的.NoteManager。前者的用途我们介绍过了，而后者主要就是记住有哪些项目，以及一些全局的控制信息。

## 用户界面

NoteManager的用户界面是这样构思的：首先，我们对每个用户，创建了一个管理项目的后台，这个称为NoteManager Daemon，简称nmrd。这样，所有命令，无论你从哪里发出，都是由这个后台执行的，不会互相冲突。我们的NoteManager命令（简称nmr），都直接发到nmrd上，由nmrd执行。nmrd同时会启动一个webui界面，允许你在本机，或者在其他机器上直接管理所有工程。

这样，我们实际上就有两个接口：命令行接口和WebUI接口。两个接口功能基本上是类似的，只是设计得更适合那个接口执行。比如，你要在命令行上立即编辑某个笔记，你用nmr search去找某个关键字，在命令行上会返回每个笔记文件的目录，允许你直接编辑那个文件。但同时，webui上也会显示所有的搜索结果，你可以直接在webui上点击这个链接，直接查看对应的文件。进入特定的笔记，在webui上你可以直接选择编辑，在webui上更新文件。而同时，如果你在命令行上编辑那个文件，监控功能也能在你保存以后，在webui上把你新的编辑更新进来。当然，有些功能只能在命令行上做，比如关掉nmrd。也有写功能只适合在webui上做，比如你在编辑某个笔记的时候，用Ctrl-V把某幅截图拷贝到笔记上。这个在命令行上要你把截图先保存成文件，然后在笔记上写对应的链接。这种工作就不适合在命令行上一步到位，而webui上就可以。

用户可以灵活组合这两种操作，更快完成工作。

我还写了一个手机软件：[本地管家](https://atomgit.com/Kenneth-Lee-2025/local_manager)，支持把html目录压缩成zip文件，可以在手机上直接查看。

我们前面说了，你可以把工程的.NoteManager/html直接打包，这个目录就是可以当作一个完整的html网站使用。但这个在本地管家显示出来效果并不好，因为我们为了让PC好用，会增加越来越复杂的界面元素，而在手机上我们最多只是为了容易看，不是为了编辑它，所以我们会额外做了一个export功能（同样在命令行和webui上都提供），让你生成一个简单版本的.html.zip文件，可以在本地管家上完成除了编辑以外的所有阅读和查找功能。

顺便说一句，如果你只是要分享几个md或者rst文件，而不是要生成html，本地管家是支持.md.zip和.rst.zip格式的。那种情况下，你甚至都不需要NoteManager的支持，可以直接把几个md或者rst文件压缩一下，直接在本地管家就可以查看渲染结果。

我原来做了另一个rst/md的渲染工具：[markdown_quickview](https://atomgit.com/Kenneth-Lee-2025/markdown_quickview)，那个可以独立渲染某个md/rst文件，这个功能现在我合并到本工具上了。你可以用nmr view命令渲染某个rst/md文件，如果这个文件在管理的项目之内，这会直接使用渲染好的结果，如果不在，也能临时渲染一个文件供查看。后者和前者的唯一区别是后者不是个工程，所以你引用其他rst/md文件可能引用不了。

## 安装

### 方式一：正式安装（推荐）

```bash
pip install NoteManager
```

如果你用uv，就是这样：
```bash
uv tool install NoteManager
```

### 方式二：源代码安装

如果你下载的是源代码，而且打算调试，就在源代码目录中用类似这样的命令：

```bash
pip install -e .
uv tool install -e .
```

依赖：Python >= 3.10，自动安装 `docutils`、`Markdown`、`pygments`、`watchdog`。

### 从源码生成安装包（wheel / sdist）

在仓库根目录（含 `pyproject.toml`）执行：

```bash
pip install build
python -m build
```

完成后在 `dist/` 目录会得到：

| 文件 | 说明 |
|------|------|
| `notemanager-<版本>-py3-none-any.whl` | Wheel，可直接分发或 `pip install` |
| `notemanager-<版本>.tar.gz` | 源码发行包（sdist），供索引或再次构建 |

本地安装刚生成的 wheel 做验证：

```bash
pip install dist/notemanager-*-py3-none-any.whl
```

## 使用

### 启动nmrd

```bash
notemanager start
# 或
nmr start

# 重启（默认沿用当前 daemon 的端口）
nmr start --restart
# 或短参数
nmr start -r
```

Daemon 启动后自动开启 Web 控制面板，默认地址：http://localhost:19833

如果你使用其他命令行命令，而nmrd没有启动，也不会影响你直接运行那些命令，它们会
自动nmrd后台的。除非你要立即使用webui，否则不需要主动去启动nmrd的。比如你写了
一个临时的md文件，你直接nmr view xxx.md就可以了。它会自动启动nmrd，然后打开浏
览器渲染这个文件的。

### 添加监控目录

```bash
notemanager add /path/to/your/notes
# 或
nmr add /path/to/your/notes
```

添加后自动执行首次构建并开始监控文件变化。若目录较大，`nmr add` 会持续输出构建进度。

### 可选界面美化插件（UI Plugin）

默认不配置时，界面保持当前基础风格。

若希望启用内置美化主题，请在项目根目录创建 `.nmrui.json`：

```json
{
  "plugin": "modern"
}
```

然后执行一次 `nmr rebuild` 即可生效。

可通过下述配置关闭插件：

```json
{
  "enabled": false
}
```

### 其他命令

```bash
nmr status                  # 查看 daemon、项目信息与所有 Web 页面 id
nmr list                    # 列出所有监控中的目录
nmr remove <目录>           # 停止监控并删除生成的文件
nmr default [工程]          # 设置/查看默认工程
nmr main [页面id]           # 查看/设置主页面（view/search 的默认目标）
nmr start --restart/-r      # 重启 daemon；端口按 config.json / CLI 参数解析
nmr --version               # 显示 NoteManager 版本
nmr launch                  # 启动 daemon 并打开 Web UI
nmr desktop                 # Windows：在桌面创建 NoteManager 启动入口
nmr stop                    # 停止 daemon
nmr view <文件>             # 临时渲染一个文件
nmr check <文件>            # 检查一个文件有没有语法错误
```

### 控制面板

打开 `http://localhost:19833` 后：

- 「添加目录」直接输入目录绝对路径；添加后表单下方会持续显示构建进度，不会看起来失去响应；
- 添加目录会在后台构建并显示进度，首次构建不会让页面看起来没反应；
- 「诊断日志」可以直接查看 `daemon.log` 末尾，无需自己找日志文件。

### 导出手机用 .html.zip（export）

面向 [本地管家](https://atomgit.com/Kenneth-Lee-2025/local_manager) 等应用：在**临时目录独立渲染**工程内 `.md`/`.rst`，再打 zip，**不**打包工程下已有的 `.NoteManager/html`（避免与控制台复杂页混用，便于以后分别演进）。

**页面特点**：仅保留渲染结果（KaTeX、Mermaid 等与控制台一致）；无侧栏、无「源文件 / 诊断」、不调用 Daemon。**首页（`index.html`）** 独占「查找」与文档树；**笔记页** 顶栏只有 **首页**（回到首页再查）和标题，本页目录用 `<details>` 折叠在同一页内，无弹层。**再查其他笔记**时请点 **首页**，保证手机上每次只呈现一个完整页面层次。

**命令行**（需 Daemon 在线以解析 `-p` 工程，导出在本地执行）：

```bash
nmr export [-p 工程] [--output 路径.html.zip]
```

未指定 `--output` / `-o` 时，默认写入**当前工作目录**下 `<工程目录名>.html.zip`。

**Web 控制台**：各项目行的「**导出ZIP**」按钮会向 `POST /api/export_zip`（JSON：`{"project": <工程下标>}`）请求 zip，浏览器下载得到同名 `.html.zip`。

### 搜索、编辑与联动

```bash
nmr search <关键词> [-p 工程]
```

- 将搜索请求推送到 WebUI（自动跳到目标项目并显示结果）
- 同时在命令行输出所有匹配结果对应的源文件绝对路径，便于复制后自行 `cd`

```bash
nmr search <关键词> [-p 工程]
```

- 交互式选择搜索结果
- 输入数字后直接用 `$EDITOR` 打开对应源文件（例如 `export EDITOR=vim` 或 `export EDITOR="code -w"`）

```bash
nmr view <文件路径.md|.rst|.txt>
```

- 若文件属于已管理项目：跳转到该文件对应的项目 HTML 页面
- 若文件未纳入管理：临时渲染单文件页面（`/temp/...`）并跳转显示
- 默认只影响**主页面**；用 `--id <页面id>` 指定其他页面，或 `--new` 新开一个页面

### 多页面与主页面

每个浏览器 tab 会在 `window.name` 里保存一个稳定的页面 id，刷新/跳转后不变；新开的 tab 是新的从页面。页面 id 可以用自动生成的随机值，也可以在 `--new` 后指定一个容易记忆的名字。

- **主页面**：第一个打开的页面。`nmr view` / `nmr search` 默认只发给它，不再影响其他页面。
- **从页面**：后续打开的页面，默认不接收命令；可用 `nmr view --id <id>`、`nmr search --id <id>` 精确指定。
- **新页面**：`nmr view --new` / `nmr search --new` 会新开 tab，并打印新页面 id，后续可用 `--id` 继续控制它。
- **命名页面**：`nmr view 文件 --new notes` 会使用 `notes` 作为页面 id；如果该 id 已经连接，就在那个页面中打开，不再新建 tab；不存在才新建。
- 页面 id 可包含字母、数字、下划线和连字符，长度 1-40；推荐把 `--new` 放在文件/关键词之后，或写成 `--new=notes`，避免可选参数把位置参数吞掉。
- 当前页面右上角会显示 `页面: <id>`；点击即可复制，不必再用 `nmr status` 查找 id。
- **主页面关闭/刷新**：刷新或跳转有 3 秒宽限期，同一 id 重连后仍是主页面；真正关闭后，最近活动的从页面自动继任。也可用 `nmr main <id>` 手动切换。
- `nmr status` 会列出所有页面 id、所属工程、当前路径和主页面标记；`nmr status --json` 输出机器可读格式。

```bash
nmr status
nmr view notes/design.md --new notes
nmr view notes/design.md --new=notes
nmr view other.md --id notes

nmr search 关键词 --new search
nmr search 关键词 --id search
nmr main search
```

> 升级后已有的工程页需要执行一次 `nmr rebuild` 才会加载新的页面 id 脚本；临时页会自动刷新。

### 在外部编辑器中打开

托管工程页和临时单文件页的顶部工具栏都有「**外部编辑**」按钮，点击后由 daemon 启动本机编辑器打开当前源文件。

默认目标是 **gvim**：

- Linux/Windows：启动 `gvim` / `gvim.exe`，每次点击新实例；
- macOS：优先 `mvim`，其次是 `/Applications/MacVim.app`；MacVim 通常复用已有实例，由其自身决定；
- 需要精确控制复用行为时，可在 `editor` 中自行加 `--remote-tab-silent`。

可通过 `~/.NoteManager/config.json` 的 `editor` 覆盖，支持字符串或数组，占位符 `{file}`、`{dir}`：

```json
{
  "editor": ["gvim", "{file}"]
}
```

```json
{
  "editor": ["code", "-r", "{file}"]
}
```

```json
{
  "editor": ["gvim", "--remote-tab-silent", "{file}"]
}
```

说明：

- 配置中的命令直接以 argv 方式执行，不经过 shell；
- 修改 `config.json` 中的 `editor` 后需要**重启 daemon** 才生效（配置在 daemon 启动时读取）；
- gvim 需要图形会话环境（`DISPLAY` / `WAYLAND_DISPLAY`），建议从桌面终端启动 daemon；
- 如果网页编辑器中有未保存修改，会先确认“外部编辑器打开的是磁盘版本”；
- 托管页的源文件保存后由 watcher 重建并刷新页面；临时页由现有的 `/temp/check` 轮询刷新。

> 升级后已有工程页需要执行一次 `nmr rebuild` 才会复制新的 `nm-external-editor.js` 并显示按钮；临时页会自动刷新。

### 配置文件编辑器

控制台标题旁的「**配置文件**」链接（或直接访问 `/config`）可以打开配置文件编辑器。
页面按类型分为工程、网络、外部编辑器几个区域，用具体输入项修改
`~/.NoteManager/config.json`：

- 工程：监控目录列表、默认工程
- 网络：TCP 端口、Web 端口、传输方式、Socket 路径
- 外部编辑器：默认 gvim/MacVim，或自定义命令
- 高级：原始 JSON（用于修复或编辑表单未覆盖的字段）

```bash
# 修改保存后，重启 daemon 生效
nmr start --restart
```

- 保存只写文件，不会热加载，也不会自动重启；
- 只要配置文件与当前运行实例不一致，配置页面和控制台会持续提示，
  重新打开页面/从浏览器后退返回也不会消失，直到执行 `nmr start --restart`；
- `nmr status` 也会显示“配置: 有未重启修改”；
- 重启时显式传入的 `--port` / `--web-port` 会覆盖文件值，且不写回文件；
- 保存前会校验 JSON 和已知字段类型；端口、目录、编辑器命令等只做警告；
- 保存时自动保留上一版 `config.json.bak`，页面可以「加载上一版」；
- 表单保存会保留配置文件中表单未覆盖的未知字段；
- 配置文件中的 `port`、`web_port`、`transport`、`socket_path` 现在都会在
  daemon 启动时读取，因此改端口后必须重启；
- 旧配置没有 `web_port` 时，启动使用当前运行值/内置默认值。

> 注意：旧版本遗留的 `config.json` 可能包含与实际运行不一致的 `port`，
> 现在这些值会真正参与启动。升级后建议先核对一次配置。

### Web 控制面板

启动 daemon 后访问 http://localhost:19833 ，可以：

- 查看所有监控目录及其状态
- 添加/移除目录
- 手动触发重建
- **导出ZIP**：生成上述手机用 `.html.zip`
- 进入项目页面浏览 HTML 输出（侧边栏 Home 回到该项目站点主页）；渲染表格默认按内容宽度显示，窄表不会横贯整页，宽表可横向滚动；表头、斑马纹和悬停样式统一
- 需要回到管理界面时，在浏览器地址栏打开 http://localhost:19833/ 即可
- 进入具体文档后，侧边栏面包屑显示「控制台 › 工程 › 各级目录 › 文档」；点击目录会回到工程主页并展开/定位该目录，方便查看同目录其他文档
- 在「源文件」页签可用内置编辑器修改 `.md`/`.rst`/`.txt`，保存按钮为「保存退出」；离开源文件时若有未保存修改，可选择保存并退出、不保存退出或取消；Vim 模式下 `:w` 只保存并停留在源文件，`:wq` / `:x` 才保存并退出；`:help` 查看新建笔记、粘贴图片、导入资源、引用资源、表格/公式编辑和删除等命令。工具栏有统一的「编辑/插入对象」按钮：光标在表格上自动打开表格编辑器，在公式上自动打开公式编辑器；都不匹配时弹出「新建表格 / 新建公式」选择框。表格支持图形化增删行列、单元格和列对齐；公式支持 Markdown/reST 行内/行间识别、KaTeX 实时预览，以及分数、根号、上下标、求和、积分、希腊字母和矩阵模板。页面右上角同时显示可复制的源文件绝对路径。粘贴剪贴板中的截图会保存到源文件目录的 `_static/` 并插入引用（详见 `docs/web-source-editor.md`、`docs/table-editor.md` 和 `docs/math-editor.md`）
- 标签页快捷键：`Ctrl/⌘+Alt+1/2/3` 切换到渲染 / 源文件 / 诊断；如果桌面环境占用了数字组合键，用 `Ctrl/⌘+Alt+C` 切换到源文件；
- 分屏快捷键：`Ctrl/⌘+Alt+S`；请求外部编辑器：`Ctrl/⌘+Alt+E`；
  回到当前目录：`Alt+↑` 或 `Ctrl/⌘+Alt+U`（文档页可用）

### 项目主页概览 / 目录关系图

每个工程构建后会生成一个概览主页：

- **目录概览**：从中心向外展示径向目录关系图；圆形直径表示文档数，
  顶层重要目录高亮，近期修改用绿点标记；点击任意节点都会同步左侧目录树，
  有子目录的节点同时把它设为新的根；支持返回/根/面包屑；
  图旁有比例滑块、适应和重置按钮，可按容器或手动比例查看；
- **主题**：从标签、索引词、重复章节和文档标题提取，与目录分开；
- **核心文档 / 最近更新**：按入链、章节数和修改时间排序；
- **主题页** `topics.html`：列出主题下的文档、章节和摘录；
- 不在主页面重复文件列表；文件浏览由左侧目录树承担；
- 左侧侧边栏目录树默认折叠，只显示一级目录；目录中的 `index` 笔记按普通笔记显示；搜索仍然保留。

概览完全在构建时生成，离线可用，不依赖 LLM。`full_build`、增量更新和删除
文件后都会同步刷新。设计细节见 `docs/project-overview.md`。

### 关于 `index` 文件

- **项目根目录的 `index.rst` / `index.md`**：保留给项目主页入口；项目概览页会生成
  `index.html`，因此根 index 的正文不会作为普通文档显示。不要在根 index 中存放
  只有普通文档才需要阅读的正文，改用其他文件名。
- **子目录中的 `index.rst` / `index.md`**：按普通笔记处理，正常进入目录树和搜索；
  如果它的标题与目录名相同，目录树会出现同名的目录节点和文件节点，这是正常结果，
  不是文件丢失。

### 文档关系 / 反向链接

每篇文档页底部新增「文档关系」：

- **同目录**：同一目录下的其他笔记，便于继续浏览相邻内容；点击标题会回到项目主页并展开该目录，快捷键 `Alt+↑` / `Ctrl/⌘+Alt+U`；
- **被引用**：哪些文档链接到这里；
- **引用**：这篇文档链接到哪些文档；
- **相关文档**：基于共享标签、章节标题、索引词、直接链接和词项相似度；
- **孤立文档**：没有入链也没有出链的文档会显示标记。

关系数据在构建时生成到 `_index/relations.json`，页面通过
`_static/nm-relations.js` 加载。它不依赖 LLM；关系数据缺失或 fetch 失败时
面板自动隐藏，不影响正文、搜索和目录图。

```bash
nmr rebuild
```

### 我的阅读 / 自上次访问

项目首页统计信息下方新增「我的阅读」：

- **自上次访问以来**：显示两次访问首页之间修改的文档；
- **待读 / 已读**：文档页可标记已读/未读；打开文档 2 秒后自动标为已读；
- **星标**：标记关注文档；
- **最近打开**：最近访问的文档。

阅读状态保存在浏览器 `localStorage`，按工程隔离，不需要账号或后端数据库。
构建时生成 `_index/activity.json`，页面通过 `_static/nm-reading.js` 加载。
状态缺失或 fetch 失败时面板自动隐藏，不影响正文、搜索和目录图。

### 命令面板 / 快捷视图

在项目首页和文档页按 `Ctrl+K` / `Cmd+K` 打开命令面板：

- 搜索并打开文档、章节、标签、索引词；
- 支持 `chapter:`、`dtag:`、`index:`、`label:`、`fname:`、`grep:` 查询前缀；
- 搜索词按正则处理：`chapter:pi` 是子串，`chapter:^pi$` 是完整标题，
  `chapter:\bpi\b` 是完整单词；
- `↑` / `↓` 选择，`Enter` 打开，`Esc` 关闭；
- 可执行返回首页、控制台、复制当前链接等动作。

输入查询后可以选择「保存查询为视图」，保存后的搜索视图会显示在项目首页的
「快捷视图」区域，点击即可重新执行搜索。视图保存在浏览器 `localStorage`，
按工程隔离，不需要后端服务。

侧边栏搜索框下方常驻 `Ctrl/⌘ K 命令面板 · 快捷键说明` 提示；
点击「快捷键说明」会打开快捷键帮助。搜索框右侧的 `?` 弹窗里也列出了
命令面板快捷键。

### 目录级新建 / 删除笔记

项目首页目录树支持：

- 目录右侧 `+`：在该目录新建笔记；
- 侧边栏顶部「＋ 新建」：在**当前文档所在目录**新建；在项目首页时仍在根目录新建；
- 文件右侧 `×`：删除笔记；
- 文档页右上角「删除」：直接删除当前正在阅读的笔记。

新建使用弹窗填写文件名和格式，创建后直接打开。删除会先显示背链和图片引用影响，
再把源文件移到 `.NoteManager/trash/<时间戳>/`，不会直接永久删除。
从文档页删除后会回到项目首页，并自动把目录关系图定位到该文档所在目录。
P1 已增加图片引用索引、独占图片清理和回收站恢复；详见「图片清理与回收站」。

### 图片清理与回收站

构建时生成 `_index/assets.json`，记录每张本地图片被哪些源文件引用。

删除笔记时：

- 只被本文引用的图片可以一起删除，默认勾选；
- 共享图片永远不会自动删除；
- 笔记和图片一起进入 `.NoteManager/trash/<批次>/`；
- 侧边栏「回收站」可以查看和恢复最近的删除批次；
- 侧边栏「资源」可以列出未引用图片，选中后移到回收站。

图片清理目前只处理图片扩展名；按笔记划分附件目录会在后续阶段实现。

### 粘贴图片 / 导入资源

源文件编辑器中粘贴图片时，图片会保存到源文件所在目录的 `_static/`：

```text
学习笔记/
  foo.md
  _static/
    nm-paste-foo-20261124-123456-abcd.png
```

文件名包含笔记名，Markdown/reST 中插入 `_static/...` 链接。现有图片不迁移；
图片引用索引、共享保护和「资源」清理继续适用。

源文件工具栏还提供：

- **粘贴图片**：从剪贴板读取图片；
- **导入资源**：选择本地文件或填写 URL，资源会复制到当前目录的 `_static/`。

导入本地文件/URL 的详细规则见 `docs/asset-import.md`。

### 引用已有资源

在源文件工具栏点「引用资源」，可从工程已有图片中选择并插入 Markdown/reST 引用：

- 默认筛选当前笔记目录的 `_static`；
- 可切换为当前目录及子目录、未引用资源、全部资源；
- 支持路径搜索和多选；搜索支持 `*.png`、`*.[jpg|png]`、`*.{jpg,png}` 等 glob 写法；
- 插入的是相对路径引用，不复制图片文件。

资源清理窗口仍只列出未引用图片，避免把所有工程资源混在一起。

### 图片标注

图片右下角可打开「缩放」和「标注」：

- 「缩放」预览显示宽度，生成 Markdown/reST 写法，并可直接写入源文件；
- 「标注」在图片上添加圈、框、箭头、直线和文字；
- 标注支持选择、移动、调整大小、修改文字、虚线、线宽、文字大小和填充透明度；
- 支持 Shift 多选、框选、整体移动/删除，以及 Delete、方向键、Ctrl+A 等热键；
- 支持导出可分享的自包含 SVG（原图 + 标注），可直接在 Markdown/reST 中引用。

标注保存为同名 `.ann.svg`，不修改原始图片；Markdown/reST 仍只引用原图，
NoteManager 渲染时自动叠加 SVG 标注层。

详见 [图片标注](docs/image-annotations.md)。

### 文档语法

NoteManager 支持 reST、Markdown 和纯文本。除标准语法外，还支持：

- reST `:dtag:` / Markdown `#tag` 文档标签；
- reST `.. index::` / `:index:` 索引词；
- reST label / `:ref:` / `:doc:` 交叉引用；
- 中文段落内软换行自动合并；
- KaTeX 数学公式、Mermaid 图表、代码高亮；
- 目录级 `_static/` 图片约定。

完整写法见 [reST / Markdown 扩展语法与书写约定](https://github.com/Kenneth-Lee/NoteManager/blob/master/docs/%E7%AC%94%E8%AE%B0%E6%A0%BC%E5%BC%8F%E8%AF%B4%E6%98%8E.md)。

### 扫描格式与忽略规则

- 受管理项目默认扫描并渲染：`.md`、`.rst`、`.txt`（txt 按段落简单渲染）。
- 可在项目根创建 `.nmrignore` 跳过目录或文件（gitignore 风格子集）：
  - `build/` 忽略目录及其下所有内容
  - `*.draft.md` 忽略匹配文件
  - `!notes/keep.txt` 反向包含（覆盖前面的忽略）

含 `/` 的模式相对项目根目录匹配。例如 `_static/*.*` 只匹配根目录下的
`_static`，不会误匹配 `sub/_static`；不带 `/` 的模式（如 `*.png`）则匹配
任意层级的同名文件。

`.nmrignore` 同时作用于**笔记扫描和资源索引**：

- 被忽略的图片不会出现在「资源」；
- 不会被当作未引用图片清理；
- 即使被文档引用，也只作为未托管资源渲染，不参与自动删除。

因此可以把 Sphinx 项目的构建产物、模板图片等其他用途的资源加入忽略规则，避免误清理。

### 可移植性

每个被管理的目录下会生成 `.NoteManager/` 子目录，其中的 `html/` 目录是完整的可浏览站点。将整个 `.NoteManager/` 拷贝到任何有浏览器的地方都能使用，包括搜索功能。

拷贝后的页面若**不是**通过控制台 Web 的 `/p/<工程号>/…` URL 打开，「源文件」页签会自动变为**只读纯文本**（不调用保存 API，避免报错）；在线编辑仅在本机通过控制台进入工程页面时可用。

## 目录结构

被管理目录下的 `.NoteManager/`：

```
.NoteManager/
├── html/                   # 渲染后的 HTML，保持原目录结构
│   ├── index.html          # 项目概览 / 目录关系图主页
│   ├── topics.html         # 全部主题页
│   ├── _index/
│   │   ├── search_index.json
│   │   ├── dtag_index.json
│   │   ├── ref_labels.json
│   │   └── overview.json   # 概览数据
│   └── _static/
│       ├── notemanager.css
│       └── notemanager.js
└── status.json
```

全局配置在 `~/.NoteManager/`：

```
~/.NoteManager/
├── config.json     # 监控目录列表和端口配置
├── daemon.json     # daemon 运行时信息（PID、端口）
└── daemon.log      # 后台日志
```
