# 图片标注（图像矢量标注层）

状态：实现中
范围：在已渲染图片上添加圈、框、箭头、直线和文字，不修改原始图片。

## 1. 目标

用户不只是想在图片下面写说明，而是希望在图片上：

- 用圈圈出重点区域；
- 用矩形框住区域；
- 用箭头指向某个点；
- 在图片文字下画直线；
- 在图上直接写文字说明。

因此标注是一层 **矢量图形叠加层**，不是文本注释，也不修改原图。

## 2. 文件结构

```text
_static/
  diagram.png
  diagram.png.ann.svg
```

- `diagram.png`：原始图片，永远不修改；
- `diagram.png.ann.svg`：透明 SVG 标注层；
- Markdown/reST 仍然只引用原图，不需要新语法。

`diagram.png.ann.svg` 不含底图，只含矢量图形：

```svg
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 1600 900">
  <ellipse cx="420" cy="260" rx="180" ry="110"
           fill="none" stroke="#e53935" stroke-width="4"/>
  <line x1="720" y1="420" x2="1050" y2="600"
        stroke="#e53935" stroke-width="3"
        marker-end="url(#arrow)"/>
  <path d="M 300 330 L 620 330"
        stroke="#e53935" stroke-width="4"/>
  <text x="740" y="390" font-size="28" fill="#e53935">
    请重点关注这个地方的问题
  </text>
</svg>
```

## 3. 渲染

页面加载后，`nm-annotations.js`：

1. 找到正文中的图片；
2. 查找同名 `.ann.svg`；
3. 把标注 SVG 内联叠加到图片上；
4. 图片保持原尺寸/响应式缩放，SVG 使用同一个坐标空间。

这样：

- 不要求 Markdown/reST 支持新的图片语法；
- 缩放页面时标注跟着缩放；
- 不依赖 SVG `<img>` 加载外部底图；
- 原图仍然可以作为普通图片单独使用。

## 3.1 图片显示尺寸

图片右下角「缩放」可以预览不同显示宽度，并生成对应源码：

Markdown（需要 `attr_list`，已启用）：

```markdown
![图](_static/diagram.png){width=480px}
```

reST：

```rst
.. image:: _static/diagram.png
   :width: 480px
```

缩放面板只预览显示宽度，不会修改源文件；复制生成的代码后，重新构建才会固定尺寸。

## 4. 编辑器

图片右下角会出现「标注」按钮。打开后：

- 圈：拖动绘制椭圆；
- 框：拖动绘制矩形；
- 箭头：拖动绘制箭头；
- 直线：拖动绘制直线；
- 文字：点击位置后输入文字；
- 颜色、线宽、线型（实线/虚线）和文字大小可选；
- 封闭图元（圈、框）支持填充颜色和填充透明度；
- 选择工具：选中已有图元后拖动移动，拖动控制柄调整大小；
- Shift+点击、框选可以多选；
- 多选后可整体移动、删除，属性修改会应用到所有选中图元；
- 箭头/直线两端都有控制柄，零长度箭头也可以拉出箭身；
- 双击文字或点「改文字」修改文字；
- 删除选中图元、清空；
- 保存到 `.ann.svg`。

默认线宽为 5px，可选范围 1–32px；文字默认 28px，可选 12–96px。
填充颜色单独选择，默认关闭；填充透明度可选 0–100%。

所有图元（圈、框、箭头、线、文字）都进入同一个图元列表，拥有独立的
选中、移动、调整大小、属性修改和删除逻辑。

### 热键

| 键 | 功能 |
|---|---|
| `Delete` / `Backspace` | 删除选中图元 |
| `Esc` | 关闭编辑器 |
| `Ctrl/Cmd+A` | 全选 |
| `Ctrl/Cmd+D` | 复制选中图元 |
| 方向键 | 移动 1px |
| `Shift+方向键` | 移动 10px |

多选目前只支持整体移动、删除和共同属性修改，不支持整体缩放。

编辑器坐标使用原图像素坐标，通过 `viewBox` 适配显示尺寸。

当前版本没有实现：

- 自由手绘；
- 选中/移动/缩放单个已有标注；
- 删除单个已有标注（使用选择工具后点「删除」）；
- 多个标注层；
- 手机手势优化。

## 5. 保存

前端调用：

```text
POST /api/save_annotation
{
  "project": 0,
  "image_rel_path": "sub/_static/diagram.png",
  "svg": "<svg ...>...</svg>"
}
```

后端：

- 校验图片路径必须位于工程目录内；
- 只接受图片扩展名；
- 拒绝包含脚本/iframe/事件属性的 SVG；
- 写入同名 `.ann.svg`；
- 同步复制到生成的 HTML 资源目录；
- 不修改 Markdown/reST 源文件。

## 6. 导出与可移植性

### 导出可分享 SVG

编辑器提供「导出 SVG」，生成一个**自包含**文件：

```text
_static/diagram.png.annotated.svg
```

这个文件把原图以 base64 内嵌，并包含矢量标注，可以直接作为普通图片引用：

```markdown
![图](_static/diagram.png.annotated.svg)
```

```rst
.. image:: _static/diagram.png.annotated.svg
```

这样即使对方没有 NoteManager，也能看到带标注的图片；原图和 `.ann.svg`
仍然保留，便于以后继续编辑。

导出完成后，结果窗口提供「撤销导出」，会删除刚生成的 `.annotated.svg`；
如果已经关闭窗口，导出的 SVG 会作为普通未引用图片出现在「资源」里，可以
在那里清理或再次引用。


- NoteManager 页面和它生成的静态站点可以显示叠加层；
- 普通 Markdown 查看器不会自动叠加 `.ann.svg`；
- 后续可以增加「导出带标注图片」：
  - 自包含 SVG（底图 base64 内嵌）；
  - 扁平化 PNG。
- 导出物适合发布到 GitHub 或其他 Markdown 查看器。

## 7. 资源生命周期

删除独占图片时，配套的 `.ann.svg` 会一起进入回收站，并在恢复图片时一起恢复。

- `.ann.svg` 不作为独立图片资源显示；它是否被使用由对应的原图决定；
- 删除原图时 `.ann.svg` 跟随进入回收站；恢复时一起恢复；
- 删除图片时应考虑连带处理标注文件；
- 图片尺寸变化后，标注可能错位，后续应提示或重新适配。

## 8. 当前限制

- 仅支持图片扩展名（png/jpg/jpeg/gif/webp/bmp/ico）；
- 标注层只保存在本地工程，不支持多人协作；
- 普通 Markdown 查看器不显示标注；
- 静态页面如果通过 `file://` 打开，fetch `.ann.svg` 可能失败；
- 还没有导出扁平化图片。
