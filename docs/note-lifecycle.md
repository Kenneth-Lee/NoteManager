# 目录级新建 / 删除笔记（P0）

状态：已实现（P0）
日期：2026-11-24
范围：项目首页目录树中的新建和删除操作

## 1. 目标

- 不进入源文件面板也能在指定目录新建笔记；
- 从目录树直接删除笔记；
- 删除默认进入工程回收站，避免误删；
- 删除前显示背链和图片引用影响；
- 图片清理留到下一阶段，不在 P0 中自动删除。

## 2. 新建笔记

入口：

- 侧边栏顶部「＋ 新建」：在项目根目录新建；
- 每个目录摘要右侧的 `+`：在该目录新建；
- 新建弹窗包含：目标目录、文件名、类型（Markdown / reST）。

后端：

```text
POST /api/create_note_in_dir
{
  "project": 0,
  "dir_rel_path": "sub",
  "filename": "new note",
  "source_ext": ".md"
}
```

- 目录必须存在，且位于工程根目录内；
- 拒绝 `..`、绝对路径和 `.NoteManager`；
- 文件名不允许路径分隔符和非法字符；
- 已存在同名文件时拒绝；
- 创建后执行 `update_file`，返回 `source_rel_path` / `html_rel_path`；
- 前端创建成功后跳转到新 HTML。

原有的 `/api/create_note`（当前文档同目录）保留。

## 3. 删除笔记

入口：

- 文档页右上角的「删除」按钮；
- 首页目录树文件行右侧的 `×`；
- 源文件面板的「删除当前笔记」（原有入口，行为改为回收站）。

文档页删除完成后会回到项目首页，并自动把目录关系图定位到该文档所在目录
（`index.html#nm-dir=<目录>`），避免删除后重新在根目录里找上下文。

删除前调用：

```text
POST /api/note_delete_info
{ "project": 0, "source_rel_path": "sub/note.md" }
```

返回：

- 背链数量和前几条背链；
- 源码中引用的图片数量和前几条图片；
- 标题、HTML 路径。

删除时：

```text
POST /api/delete_note
```

源文件移动到：

```text
.NoteManager/trash/<YYYYmmdd-HHMMSS>/<原相对路径>
```

随后执行 `remove_file`，删除 HTML 并重建索引、关系、activity 和首页。

如果索引更新失败，会尝试把文件从回收站移回原位置。

## 4. 图片

P0 不会自动删除图片。删除弹窗会提示：

- 文中图片引用数量；
- 这些图片不会被自动删除；
- 后续版本会基于资源引用索引判断独占/共享资源。

## 5. 限制

- 回收站目前没有 Web 恢复界面，需要从 `.NoteManager/trash/` 手动恢复；
- 不删除空目录；
- 不支持重命名、移动、批量操作；
- 新建笔记内容仍是内置模板；
- 目录树操作只在项目首页出现；根目录「＋ 新建」在所有工程页面可用；
- 独立导出 HTML 没有 `/p/N/` Web 上下文，不提供这些操作。

## 6. 测试

- 首页目录树包含 `+` 和 `×` 操作；
- `create_note_in_dir` 在指定目录创建并生成 HTML；
- `note_delete_info` 返回影响信息；
- 删除后源文件和 HTML 消失，源文件出现在 `.NoteManager/trash/`；
- 既有测试不回归。
