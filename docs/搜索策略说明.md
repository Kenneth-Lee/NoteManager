# 搜索策略说明

本文说明NoteManager的搜索策略定义。

首先，NoteManager在后台（nmrd）通过扫描所有的md和rst文件，找到其中的关键字，从
而建立索引数据库，这些索引包括：

* chapter：章节标题

* dtag: 关键字，这个在rst中通过dtag role表示，比如:dtag:`test`。在md文件中，这
  通过#test这样的形式表达。

* index: 索引，这通常表示一个定义，在rst中用index role表示，比如:index:`test`。
  在md文件中暂时考虑用什么语法表示。

* fname：文件名，这用来索引文件名（未实现）

在搜索的时候，你可以带用正则表达式去匹配对应的位置，找到对应的章节，定义或者对
应的文档。

例如 ``chapter:pi`` 是子串匹配，可能同时命中 ``acpi``、``API``、``Pivot``；
如果只想匹配完整章节名，可以用：:

    chapter:^pi$

如果只想让 ``pi`` 作为完整单词出现（标题可以更长），可以用：:

    chapter:\bpi\b

不带类别时 ``\bpi\b`` 会在所有索引类型中做全词匹配。Web 搜索框会保留
``\b`` 等正则转义；如果写成 ``chapter:"pi note"``，引号只用于包含空格，
不会自动变成全词匹配。

搜索的时候可以带类别搜索，也可以不带类别搜索，不带类别，就搜索所有的类比，指定
类别，就仅搜索具体的类别。指定的方法如下：

> 类别:关键字

关键字中不能有空格，如果有空格，我们认为你要查询多个全部条件符合的关键字（未实现），比如这样：

> 类别:关键字 类别2:关键字2

如果你非要给关键字加空格，可以用引号把关键字包裹起来，比如这样：

> 类别:"test file"

由于我们已经提前抽取了这个关系，所以这种搜索可以很快。这种搜索我们称为带映射搜
索。

但有时我们希望可以全局去搜索所有的文本，这种情况我们需要专门去搜索特定的内容，
这是没有预先的映射的，当我们检查到你用grep作为类别进行查找时，我们不会实时查找，
而是等你完成输入并回车后，才开始查找，数据随着查找结果实时更新，如果你修改了输
入框，这个搜索就会停止，等待下一个输入。

这种搜索，称为”不带映射搜索“。

如果你需要缩小全局搜索的范围，你也可以先用带映射搜索限定查找范围，然后开始做不
带映射搜索。比如这样：

> dtag:数学 grep:"pi.*="

这样只会在带dtags为数学的文档中搜索。

带映射搜索不但用于一般的搜索，也用于我们在其他文件中不用知道某个关键字在哪里，
直接找到它。

## 快速定位策略

搜索结果除了展示匹配项，还应尽量提供可定位信息，便于点击后直接跳到目标位置：

* 对 chapter/label/index/dtag/fname 等带映射条目，优先使用 `path#anchor` 形式跳转。
* 对 grep（不带映射搜索）条目，返回 `source_path + line_start`；若无稳定 anchor，则回退到源文件行号定位。
* 前端点击结果时按以下优先级定位：`anchor` -> 渲染区节点 -> 源文件行号。
