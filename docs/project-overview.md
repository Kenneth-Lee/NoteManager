# 项目主页概览 / 主题地图设计

状态：已实现（Phase 1）
日期：2026-11-23
范围：`.NoteManager/html/index.html` 与 `topics.html` 的构建时概览

## 1. 背景

项目主页此前只有侧边栏目录树，正文基本为空。用户想找某个内容时，只能：

- 按目录逐层浏览；
- 已经知道关键词，用搜索；
- 自己记住某篇文档的位置。

缺少一个从内容结构“总结”出来的入口：让用户先看到工程里有哪些主题、哪些内容
比较核心，再一次点进最可能关心的主题。

## 2. 目标

1. 在项目主页显示统计信息、主题地图和重点主题。
2. 每个主题可以一次点击进入主题页，看到该主题下的文档、章节和摘录。
3. 显示“核心文档”和“最近更新”，作为主题之外的直接入口。
4. 保留原目录树和搜索，不破坏现有浏览方式。
5. 完全离线、构建时生成、确定性；不依赖 LLM 或网络。
6. 增量更新（`update_file` / `remove_file`）后概览同步刷新。

## 3. 非目标（Phase 1）

- 不做真正的语义摘要/生成式总结。
- 不做个性化推荐（最近浏览、搜索历史）。
- 不做 TF-IDF/嵌入聚类；无结构工程先用文档标题作为入口。
- 不做力导向知识图；主题地图使用静态 treemap。
- 不改变搜索索引和现有文档页。
- 不保证手机导出包包含新主题页（后续单独处理）。

## 4. 数据来源

全部来自现有构建产物：

- `_index/search_index.json`
  - `chapter`：章节标题、锚点
  - `dtag`：文档标签
  - `index`：RST `.. index::` 条目
  - `grep`：正文段落，用于摘录
  - `fname` / `label`：文件名与交叉引用
- 渲染后 HTML 中的内部 `<a href>`：文档引用图
- 文档路径：顶层目录作为主题
- 源文件 mtime：最近更新
- 文档标题：小工程/无结构工程的 fallback

## 5. 主题提取

按优先级：

1. **顶层目录**：`软件构架设计/...` → 主题“软件构架设计”。
2. **显式标签**：`dtag`。
3. **索引词**：RST `.. index::`，只保留至少两篇文档共享的词，避免单篇窄词。
4. **重复章节标题**：至少两篇文档出现的章节名；过滤“介绍 / 小结 / 参考 /
   其他 / 附录”等通用标题。只有目录/标签/索引主题不足 8 个时才启用，
   防止通用章节名挤掉真正的结构主题。
5. **根目录文档**：文档数 ≤ 80 时，根目录下每篇文档作为主题；大工程根目录文档
   达到 5 篇时合并为“根目录”主题。
6. **小工程/扁平工程**：没有结构主题或只有一个结构主题、且文档数 ≤ 80 时，
   用文档标题作为主题；否则用核心文档作为 fallback。

同名主题会合并（例如目录名和标签同名），主题 id 由名称哈希生成，保证锚点稳定。

主题得分：

```text
sum(文档得分) + 文档数 * 4 + 章节数 * 0.5
```

文档得分：

```text
入链数 * 5 + 章节数 * 1.5 + 标签数 * 2 + min(6, 正文块数 * 0.2)
```

## 6. 页面形态

### 6.1 项目主页

```text
项目名
N 篇文档 · M 个章节 · K 个标签 · L 条内部链接

主题地图（静态 SVG treemap）
  面积 = 主题得分；颜色 = 主题类型；点击 → topics.html#主题id

重点主题（Top 6 卡片）
  名称 / 类型 / 篇数 / 节数
  摘录
  代表文档 3 篇
  查看该主题全部 →

核心文档            最近更新
- 入链多/章节多     - mtime 最新
```

- 主题地图最多显示 12 个主题；其余聚合为“其他主题”。
- 主题地图只使用目录、标签、索引词（以及至少两篇文档共享的章节）作为瓦片。
  结构主题不足 3 个时省略地图，避免变成一堆不可读的单文档小块；此时用主题卡片
  和主题页承担入口。
- 主题卡片最多显示 6 个；全部主题进入 `topics.html`。
- 左侧目录树保留，正文概览不替代目录浏览。
- 主题摘录来自 `grep` 的第一段有效正文，截断约 170 字符。

### 6.2 主题页 `topics.html`

- 单页，按主题分段，锚点 `#topic-<hash>`。
- 每个主题显示：
  - 名称、类型、文档数、章节数；
  - 该主题的代表摘录；
  - 最多 12 篇文档；
  - 每篇文档的短摘录和前 3 个章节链接。
- 超过 12 篇时提示使用首页目录树或搜索继续查看。
- 超过 20 个主题时，剩余主题列在“更多主题”，不生成详情。
- 页面不依赖 JS，直接链接到生成的 HTML 文档。

### 6.3 Treemap

- 服务端 Python 生成静态 SVG，不引入 D3/前端依赖。
- 使用递归二分布局：按权重排序，沿长边按累计权重切分。
- 主题块带名称、篇数/类型；足够大的块额外显示一行摘录。
- 颜色按主题类型区分：目录蓝、标签绿、索引橙、章节紫、文档灰。
- 点击块跳转到 `topics.html#主题id`；“其他主题”跳 `#more`。

## 7. 构建接入

新增 `overview.py`：

- `build_overview(project_root, html_dir, documents)`：生成数据；
- `build_and_write(...)`：写 `_index/overview.json` 和 `topics.html`；
- `render_landing_overview(overview)`：主页正文；
- `render_topics_page(overview)`：主题页。

接入：

- `full_build()`：索引与 dtag/ref 写完后生成概览，再生成首页；
- `update_file()`：重建索引后重新生成概览和首页；
- `remove_file()`：删除文件并重建索引后重新生成概览和首页；
- 概览生成失败只记录日志，不阻断构建，首页回退到原“NoteManager”标题。

`overview.json` 保留给后续 UI/搜索/导出使用。

## 8. 测试

- 全量构建生成 `overview.json`、`topics.html`，主页含 treemap、主题卡片、
  目录树和 `topics.html` 链接；
- 主题提取：目录、重复章节、文档 fallback；
- 内部链接图与入链排序；
- 增量新增/删除文件后概览同步；
- SVG 在空主题和多主题下都合法；
- 文档页/搜索/导出等既有测试不回归。

## 9. 已知限制

- 摘要为抽取式，不是生成式；短文档可能没有合适摘录。
- 主题质量依赖目录、标签、索引词和章节标题；扁平且无标签的大工程
  可能需要 Phase 2 的 TF-IDF/聚类。
- 单篇索引词、单篇标签可能不进入概览。
- 主题页每主题最多 12 篇，更多内容靠目录/搜索。
- 手机导出包暂未包含主题页。
- 扁平且文档很多的工程，主题仍可能退化为文档入口；Phase 2 再用聚类/关键词
  提取提升。
