# 粘贴图片到目录级 `_static`（P3）

状态：已实现（P3）
日期：2026-11-24
范围：源文件编辑器中的图片粘贴

## 1. 目标

- 新粘贴的图片统一放到源文件所在目录的 `_static/`；
- 不采用每篇笔记一个 `.assets/` 子目录；
- 文件名包含笔记名，减少同目录多篇笔记的歧义；
- 不迁移现有图片；
- 继续兼容图片引用索引、独占清理、资源清理和回收站。

## 2. 保存规则

源文件：

```text
学习笔记/foo.md
```

粘贴图片保存到：

```text
学习笔记/_static/nm-paste-foo-20261124-123456-abcd.png
```

文件名格式：

```text
nm-paste-<笔记名>-<时间戳>-<随机串>.<扩展名>
```

笔记名会清理路径分隔符和特殊字符，最长 60 个字符。

## 3. 插入片段

Markdown：

```markdown
![]( _static/nm-paste-foo-20261124-123456-abcd.png)
```

reST：

```rst
.. image:: _static/nm-paste-foo-20261124-123456-abcd.png
```

实际插入不带 Markdown 示例中的空格。

## 4. 为什么不做每篇一个附件目录

- 同一主题的多篇笔记通常共享图片；
- 每篇一个目录会产生大量子目录；
- 用户现有习惯是目录级 `_static`；
- 如果某个主题图片特别多，可以为该主题建立独立源码目录，使用自己的 `_static`。

## 5. 兼容性

- NoteManager 扫描时跳过 `_static`，不会当作文档；
- 构建把 `_static` 复制到生成的 HTML；
- `assets.json` 会扫描 `_static` 中的图片；
- 删除笔记时按引用关系保护共享图片；
- 「资源」清理能看到 `_static` 中的未引用图片；
- 旧图片/旧目录不需要迁移。

## 6. 注意

- 不建议把用户图片直接放在工程根目录的 `_static/`，因为可能与 NoteManager 运行时静态资源命名空间混在一起；
- 推荐放在每个**源码目录**自己的 `_static/`；
- 顶层 `_static/<NoteManager运行时文件名>` 会被保留，不复制项目同名文件。

## 7. 测试

- 粘贴 PNG 保存到源文件目录的 `_static/`；
- 文件名包含笔记名；
- Markdown/reST 插入路径为 `_static/...`；
- 生成的 HTML 资源目录同步；
- 既有图片索引和清理测试不回归。
