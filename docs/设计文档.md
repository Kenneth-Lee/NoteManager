# NoteManager 设计文档

## 1. 项目目标

NoteManager 是一个本地笔记管理工具，核心能力：

- 扫描目录中的 .rst 和 .md 文件，渲染成独立 HTML
- 生成自包含的 .NoteManager 目录，拷贝到任何有浏览器的地方都能使用（包括搜索）
- 不绑定 Sphinx 或 Obsidian，原有项目中的文件可以直接纳入管理
- 统一后台 daemon 自动监控文件变化、增量更新、提供 Web 控制面板

## 2. 架构概览

```
用户 → CLI (thin client) → TCP localhost:19832 → Daemon
                                                       ├── TCP Server (CLI 命令)
                                                       ├── HTTP Server (Web UI :19833)
                                                       ├── 对每个目录维护 Observer
                                                       └── 统一调度 builder/watcher
```

**关键设计决策**：
- Python daemon 在后台持续运行，持有全局唯一状态
- CLI 是轻量客户端，通过 TCP 协议与 daemon 通信
- Web UI 通过 HTTP 提供控制面板和项目浏览
- 每个项目的 .NoteManager/html/ 是纯静态的，可独立拷贝使用

## 3. 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 语言 | Python 3.10+ | rst 解析生态完善 |
| rst 渲染 | docutils | 直接用底层解析器，不走 Sphinx 全量编译 |
| md 渲染 | Markdown 库 | 轻量，扩展丰富 |
| 搜索 | JSON 索引 + JS | 纯静态，浏览器内运行 |
| 文件监控 | watchdog | 跨平台（inotify/FSEvents/ReadDirectoryChangesW） |
| CLI 通信 | TCP + 4字节头JSON | 简单可靠，跨平台 |
| Web UI | 内置 HTTPServer | Python 内置，无额外依赖 |
| 后台化 | double-fork | Unix 标准 daemon 模式 |

## 4. 目录结构

### 项目源码

```
notemanager/
    __init__.py
    cli.py              # CLI 入口
    daemon.py            # Daemon 主体（TCP + HTTP + Observer 管理）
    protocol.py          # TCP 通信协议
    web.py               # Web 控制面板（HTTP handler + HTML）
    builder.py           # 构建引擎（全量/增量）
    watcher.py           # 文件监控（watchdog handler）
    scanner.py           # 文件扫描
    renderer/
        __init__.py
        rst_renderer.py  # RST 渲染
        md_renderer.py   # MD 渲染
        roles.py         # 自定义 role
        directives.py    # 自定义 directive
        template.py      # HTML 模板
    indexer.py           # 搜索索引
    ref_resolver.py      # 交叉引用解析
```

### 全局配置（~/.NoteManager/）

```
~/.NoteManager/
    config.json     # 监控目录列表和端口配置
    daemon.json     # daemon 运行时信息（PID、端口）
    daemon.log      # 后台日志
```

### 项目输出（被管理目录下的 .NoteManager/）

```
.NoteManager/
    html/                   # 渲染后的 HTML，保持原目录结构
    index/
        search_index.json   # 全文搜索索引
        ref_labels.json     # label → html 路径映射
    static/
        notemanager.css
        notemanager.js
    status.json
```

## 5. 核心流程

### Daemon 启动流程

1. 启动 TCP server（CLI 通信端口 19832）
2. 启动 HTTP server（Web UI 端口 19833）
3. 读取 config.json，恢复之前监控的目录
4. 对每个目录执行 full_build + 启动 Observer
5. 等待 shutdown 信号

### 构建流程（full_build）

1. **扫描**：递归发现所有 .rst/.md 文件
2. **第一遍**：渲染所有文件，提取 label 定义
3. **第二遍**：解析交叉引用，写入 HTML
4. **索引**：生成 search_index.json
5. **输出**：写入 .NoteManager/ 目录

### 增量更新

文件变化时 watchdog 触发，debounce 0.3 秒后：
- 单文件重新渲染
- 重建 label 映射（因为 label 可能变化）
- 更新搜索索引

## 6. CLI 接口

```
notemanager start [--port PORT] [--web-port PORT]  # 启动 daemon
notemanager stop                                    # 停止 daemon
notemanager status                                  # 查看状态
notemanager add <directory>                         # 添加监控
notemanager remove <directory>                      # 移除监控
notemanager list                                    # 列出目录
```

`add` 命令会自动启动 daemon（如果未运行）。

## 7. Web 控制面板

Daemon 启动后自动在 http://localhost:19833 提供：
- 所有监控目录的状态概览
- 添加/移除目录
- 点击直接浏览各项目的 HTML 输出
- 手动触发重建

## 8. rst 兼容策略

| 构造 | 处理方式 |
|------|----------|
| 标准 rst 格式 | docutils 原生支持 |
| `:ref:` label | 自定义 role → 后处理解析 |
| `:doc:` path | 自定义 role → 映射为 .html |
| `.. toctree::` | 简化 directive |
| `.. cnote::` | 移植原实现 |
| `:dtag:` / `:dtaglist:` | 简化处理 |
| 其他 Sphinx 扩展 | 不支持，显示为原文 |

## 9. 跨平台策略

- pathlib.Path 处理所有路径
- 支持中文文件名
- watchdog 封装各平台原生 API
- TCP/HTTP 跨平台一致
- double-fork 仅 Unix 需要（Windows 另行处理）
