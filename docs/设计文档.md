# NoteManager 设计文档

## 1. 项目目标

NoteManager 是一个本地笔记管理工具，核心能力：

- 扫描目录中的 .rst 和 .md 文件，渲染成独立 HTML
- 生成自包含的 .NoteManager 目录，拷贝到任何有浏览器的地方都能使用（包括搜索）
- 不绑定 Sphinx 或 Obsidian，原有项目中的文件可以直接纳入管理

## 2. 架构概览

```
用户目录（包含 .rst/.md 文件）
    │
    ▼
┌──────────────────────────────┐
│  Python 后台（构建时运行）      │
│  ┌─────────┐  ┌────────────┐ │
│  │ scanner │  │ ref_resolver│ │
│  └────┬────┘  └─────┬──────┘ │
│       ▼              ▼        │
│  ┌──────────┐  ┌───────────┐ │
│  │ renderer │  │  indexer   │ │
│  │ rst / md │  │            │ │
│  └────┬─────┘  └─────┬─────┘ │
│       ▼              ▼        │
│       └──────┬───────┘        │
│              ▼                │
│     .NoteManager/             │
└──────────────────────────────┘
```

**关键设计决策**：Python 只在构建/索引时运行；消费端（查看和搜索）完全依赖静态 HTML + JS，不要求安装 Python。

## 3. 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 语言 | Python 3.10+ | 用户熟悉，rst 解析生态完善 |
| rst 渲染 | docutils | 直接用底层解析器，不走 Sphinx 全量编译 |
| md 渲染 | Markdown 库 | 轻量，扩展丰富 |
| 搜索 | JSON 索引 + JS (miniSearch) | 纯静态，浏览器内运行 |
| 文件监控 | watchdog | 跨平台（inotify/FSEvents/ReadDirectoryChangesW） |
| CLI | argparse | 内置，无需额外依赖 |
| 测试服务 | http.server | 内置，开发调试用 |

## 4. 目录结构

### 项目源码

```
notemanager/
    __init__.py
    cli.py              # CLI 入口
    scanner.py          # 文件扫描
    renderer/
        __init__.py
        rst_renderer.py  # RST 渲染
        md_renderer.py   # MD 渲染
        roles.py         # 自定义 role
        directives.py    # 自定义 directive
        template.py      # HTML 模板
    indexer.py           # 搜索索引
    ref_resolver.py      # 交叉引用解析
    server.py            # HTTP 服务器
```

### 输出（.NoteManager/）

```
.NoteManager/
    html/                   # 渲染后的 HTML，保持原目录结构
    index/
        search_index.json   # 全文搜索索引
        ref_labels.json     # label → html 路径映射
    static/
        notemanager.css     # 共享样式
        notemanager.js      # 搜索和导航 JS
    status.json             # 构建状态
```

## 5. 核心流程

### 构建流程

1. **扫描**：递归发现所有 .rst/.md 文件，跳过排除目录
2. **第一遍——渲染 + 标签收集**：
   - 对每个文件渲染为 HTML
   - 提取 `.. _label:` 定义，构建 label → 文件路径映射
   - 提取标题、标签等元数据
3. **第二遍——引用解析**：
   - 解析 :ref: 链接（查 label 映射）
   - 解析 :doc: 链接（路径映射为 .html）
   - 解析 markdown 链接（.md → .html）
4. **索引生成**：提取纯文本，构建 search_index.json
5. **输出**：写入 .NoteManager/ 目录

### 搜索机制

- 构建时：从 HTML 提取纯文本 → 生成 JSON 文档数组
- 运行时：JS 加载 JSON → miniSearch 在浏览器内执行搜索
- 不依赖任何后端服务

## 6. rst 兼容策略

我们不实现完整的 Sphinx 语义，而是分层处理：

| 构造 | 处理方式 |
|------|----------|
| 标准 rst 格式（标题、列表、代码块、表格） | docutils 原生支持 |
| `:ref:` label | 注册自定义 role，渲染为带 data-ref-label 的链接，后处理解析 |
| `:doc:` path | 注册自定义 role，映射为对应 .html 文件的相对路径 |
| `.. toctree::` | 注册为简化 directive，生成子文档列表 |
| `.. cnote::` | 移植原实现（改用 docutils Directive 基类） |
| `:dtag:` / `:dtaglist:` | 简化处理，构建时收集 tag 映射 |
| 其他 Sphinx 扩展 | 不支持，docutils 会显示为原文（不影响阅读） |

## 7. CLI 接口

```
notemanager build <directory>         # 扫描、渲染、索引
notemanager build <directory> --force # 强制全量重建
notemanager serve <directory>         # 启动测试 HTTP 服务器
notemanager serve <directory> --port 8080
```

## 8. 跨平台策略

- 所有路径操作使用 `pathlib.Path`
- 文件名不做任何平台假设（支持中文文件名）
- URL 中的非 ASCII 字符用 `urllib.parse.quote` 编码
- 文件监控使用 watchdog（封装了各平台原生 API）
- .NoteManager 目录以点开头（Unix 隐藏，Windows 可正常使用）

## 9. 后续扩展

以下功能在第一阶段不实现，但架构上预留空间：

- **文件监控**：watchdog + debounce，文件修改后增量更新索引
- **多目录管理**：单进程监控多个项目目录
- **增量构建**：只重新渲染有变动的文件（基于 mtime）
- **MathJax**：嵌入 MathJax.js 支持公式渲染
- **主题系统**：可替换 CSS 主题
