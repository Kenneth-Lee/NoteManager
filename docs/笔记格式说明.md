# 笔记格式说明

NoteManager现在支持三种笔记格式：

* reST。Docutils项目发布的格式，文件扩展名是.rst。这是我们主力支持的全功能格式。
  rst文件常常用于Sphinx项目，我们也会支持一些Sphinx的扩展，但不是全部。

* Markdown。
  John Gruber个人定义的的一种格式
  （[ref](https://link.wtturl.cn/?target=https%3A%2F%2Fdaringfireball.net%2Fprojects%2Fmarkdown%2Fsyntax&scene=im&aid=497858&lang=zh)），
  现在被广泛使用在不同场合，文件扩展名是.md

* 简单文本。纯文本，文件扩展名是.txt

它们其实都是普通文本文件，只是对文本的写法进行了一些惯例约定，保证既可以直接当
作文本阅读，也可以渲染成更容易阅读的其他格式（常常是html网页）。

NoteManager能自动把工程目录中的所有这些文件找出来渲染成网页，建立文件间的关联，
让你可以快速查找。用户可以在目录中加.nmrignore文件忽略部分文档。

这三种格式都有自己标准的格式定义，NoteManager支持这些基本的定义，但为了增强可
用性，NoteManager支持一些额外的扩展，这些扩展大部分和标准定义兼容，或者和其他
工具的定义一致，用户可以根据需要使用这些扩展。

本文说明我们包括哪些扩展，对于标准格式已经定义的格式，不在我们的说明范围内。

## 1. reST扩展

### 1.1 综述

我们在rst文件中支持以下标准 Docutils 能力：

- `.. image::` / `.. figure::`
- `.. note::` / `.. warning::` / `.. tip::`
- `.. code-block::`
- `.. math::`
- 简单表格、列表、引用、脚注
- 文档信息字段：
  - `:Author:`
  - `:Version:`
  - `:Date:`
  - `:Status:`

文档信息字段本身不显示在正文中，会提取到“诊断”页。下面的特性不支持：

- `.. include::` 被关闭，不能插入其他源文件；
- 完整 Sphinx 主题、扩展、`conf.py`；
- Sphinx 专有 role（如 `:term:`、`:guilabel:` 等）；
  - 未注册的 role 会被忽略，并在诊断里提示；
- 不支持的 directive 会在诊断里提示；
- Sphinx 的完整 `toctree`、自动摘要、索引生成等行为。

code-block中，我们除了支持一般的语法高亮，也支持mermaid。

不少reST渲染工具对中文处理不友好：如果在一段之中换行，在中文中会增加一个空格。
NoteManager也没有这个问题，用户不需要为了避免这种空格专门写长行。

### 1.2 扩展role

reST语法主要通过role和directive进行扩展，role是这样定义的：

```rst
  :role:参数
```

NoteManager支持大部分默认的role。渲染过程中发现的不支持的 role、directive、
文档信息字段，以及 TXT 注释等提示，都会收集到渲染页面的“诊断”中。

NoteManager支持如下额外的role：

####  dtag

这个role用于写文档的查询关键字，比如：
```rst
:dtag:`Linux, 内核, 文件系统`
```

- 可以写在正文任意位置；
- 多个标签用逗号分隔；
- 标签本身会从渲染正文中移除，只作为元数据。

dtag和index（默认支持的role）都会被作为文档的索引使用。

#### ref

这是 reST 用于引用标签的 role。标签定义写法是标准语法：

```rst
.. _my-label:

目标章节
--------
章节具体内容
```

引用：

```rst
:ref:`my-label`
:ref:`目标章节 <my-label>`
```

当前限制：

- 标签只从 `.rst` 文件中提取；
- `:ref:` 会跳到目标文档中的 label 锚点；
- 同名标签会生成候选链接，点击时由用户选择目标，同时进入诊断；
- 不能直接引用 Markdown 标题锚点或 TXT 内容；
- md/rst/txt 的统一引用设计仍在进行。

#### doc

`:doc:` 用于引用其他笔记，可以指向 `.md`、`.rst` 或 `.txt` 渲染出的文档：

```rst
:doc:`path/to/doc`
```

规则：

- 路径不写扩展名；
- NoteManager 把它映射为同名 `.html`；
- 不是根据磁盘上的实际扩展名“自动判断”；
- 同一目录下如果同时存在 `doc.md` 和 `doc.rst`，它们会竞争同一个 `doc.html`；
  这会在诊断中提示，需要重命名其中一个。

### 1.2 扩展directive

directive类似role，只是常常用于多行的情形。不少定义是同时支持role和directive两
种形态的。directive这样定义：

```rst
  .. directive:: 参数
    更多参数
```

NoteManager对directive采用role类似的处理策略。我们支持如下扩展directive：

#### toctree

当前只支持最简形式的条目列表：

```rst
.. toctree::

   foo
   bar
```

它会把每个条目渲染成指向对应文档的链接。

注意：

- `:maxdepth:` 和 `:caption:` 虽然可能被接受，但当前不会生效；
- 不支持 `:glob:`、`:hidden:`、子目录自动展开或 Sphinx 的隐式文档树；
- 条目只是简单的链接列表，不提供完整 Sphinx 目录功能。

需要可靠目录时，直接写普通文档链接更合适。

#### cnote

cnote类似 note directive，但属于NoteManager专门处理的提示格式。类似：

```rst
.. cnote:: 注意

   这里是提示内容。
```

渲染为带标题的提示块。

#### centered

这个扩展用于居中显示内容，例如：

```rst
.. centered::

   居中显示的内容。
```


## 2. Markdown

NoteManager对于Markdown文件启用如下标准插件：

- `fenced_code`
- `codehilite`
- `tables`
- `toc`
- `md_in_html`
- `attr_list`

因此支持：

- 围栏代码块；
- 代码高亮；
- 表格；
- 标题自动生成 TOC；
- Markdown 中嵌入简单 HTML；
- `attr_list` 属性写法，例如图片宽度：

```markdown
![图](_static/a.png){width=480px}
```

### 2.0 YAML 头

Markdown 和 TXT 文件可以在文件开头写一个简单的 YAML 头：

```yaml
---
tags: [Linux, 内核, 文件系统]
title: 一个标题
author: Me
---
```

规则：

- 只解析最基本的头部语法，不实现完整 YAML；
- 只使用 `tags` 字段作为 dtag；
- `tags` 支持 `[a, b]` 形式或块列表：

```yaml
tags:
  - Linux
  - 内核
```

- 其它字段（如 `title`、`author`）不参与渲染，只记录到“诊断”；
- YAML 头从正文中移除；
- 未闭合或无法解析的头部会保留为正文并产生诊断提示。

正文中的 `#tag` 仍然兼容并作为 dtag 处理；新文档建议优先使用 YAML `tags`。

不启用完整 YAML、脚注、任务列表等额外扩展。

和rst一样，md我们默认支持数学公式和Mermaid，支持中文段内换行。

### 2.1 dtag扩展

推荐在 YAML 头中写：

```yaml
---
tags: [Linux, 内核, 文件系统]
---
```

为了兼容旧文档，正文中的 `#tag` 也会被当作 dtag 处理，例如：

```markdown
这是正文 #Linux #内核
```

`# 标题` 是 Markdown 标题，不是标签；`[](#anchor)` 中的 `#` 也不是标签。
新文档建议统一使用 YAML `tags`。

### 2.2 链接

Markdown的默认链接语法，比如：
```markdown
参见 [io_uring](../Linux内核/io_uring.md)。
```
不但可以引用md文件，还可以引用其他笔记文件。（和rst不同，rst语法天然不需要写扩
展名，所以会自动判断，md语法就是要写扩展名的，所以是确指。）

Markdown 没有 RST 的 `.. _label:` 那样的跨文档标签语法；通常用标题锚点
（例如 `#section`），也可以在允许的 HTML/属性写法中显式设置锚点。

跨文档链接的扩展名会自动转换为 `.html`，并保留 `#anchor`，例如：

```markdown
[章节](other.md#section)
```

会转换为 `other.html#section`。

## 3. 简单文本文件扩展

TXT 文件除注释和 YAML 头外尽量保持原样：前导空格、行内空格和换行都保留，
不再改写成普通段落。渲染时使用 `<pre>` 风格显示，只对 HTML 特殊字符做转义。

YAML 头和 Markdown 使用同一套基本规则：

```yaml
---
tags: [Linux, 内核]
author: Me
---
```

`tags` 进入 dtag 索引，其它字段进入诊断。

### 3.1 注释

以 `nMr:` 开头（大小写敏感，必须从行首开始）的行视为注释，不显示在正文中，
但会写入“诊断”页。

```text
nMr: 这是注释 #Linux, 内核#
这一行会原样显示。
```

注释中可以写 `#标签#`，标签内容会进入 dtag 索引；多个标签用逗号分隔。
除注释行外，正文中的 `#...` 不当作 dtag。
