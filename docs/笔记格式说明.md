# 笔记格式说明

NoteManager现在支持三种笔记格式：

* reST。Docutils项目发布的格式，文件扩展名是.rst。这是我们主力支持的全功能格式。
  rst文件常常用于Sphinx项目，我们也会支持一些Sphinx的扩展，但不是全部。

* Markdown。
  John Gruber个人定义的的一种格式
  （[ref](https://link.wtturl.cn/?target=https%3A%2F%2Fdaringfireball.net%2Fprojects%2Fmarkdown%2Fsyntax&scene=im&aid=497858&lang=zh)），
  现在被广泛使用在不同场合，文件扩展名是.md

* 简单文本。纯文本，文件扩展名是.txt

它们其实都是普通文本文件，只是对文本的写法进行了一些惯例约定，保证既可以直接当
作文本阅读，也可以渲染成更容易阅读的其他格式（常常是html网页）。

NoteManager能自动把工程目录中的所有这些文件找出来渲染成网页，建立文件间的关联，
让你可以快速查找。用户可以在目录中加.nmrignore文件忽略部分文档。

这三种格式都有自己标准的格式定义，NoteManager支持这些基本的定义，但为了增强可
用性，NoteManager支持一些额外的扩展，这些扩展大部分和标准定义兼容，或者和其他
工具的定义一致，用户可以根据需要使用这些扩展。

本文说明我们包括哪些扩展，对于标准格式已经定义的格式，不在我们的说明范围内。

## 1. reST扩展

### 1.1 综述

我们在rst文件中支持以下标准 Docutils 能力：

- `.. image::` / `.. figure::`
- `.. note::` / `.. warning::` / `.. tip::`
- `.. code-block::`
- `.. math::`
- 简单表格、列表、引用、脚注
- 文档信息字段：
  - `:Author:`
  - `:Version:`
  - `:Date:`
  - `:Status:`

不可见而信息会从正文中提取并显示在诊断信息里。下面的特性不支持：

- `.. include::` 被关闭，不能插入其他源文件；
- 完整 Sphinx 主题、扩展、`conf.py`；
- Sphinx 专有 role（如 `:term:`、`:guilabel:` 等）；
  - 未注册的 role 会被忽略，并在诊断里提示；
- Sphinx 的完整 `toctree`、自动摘要、索引生成等行为。

code-block中，我们除了支持一般的语法高亮，也支持mermaid。

不少reST渲染工具对中文处理不友好：如果在一段之中换行，在中文中会增加一个空格。
NoteManager也没有这个问题，用户不需要为了避免这种空格专门写长行。

### 1.2 扩展role

reST语法主要通过role和directive进行扩展，role是这样定义的：

```rst
  :role:参数
```

NoteManager支持大部分默认的role，如果遇到不支持的role或者directive，它会自动忽
略，并在渲染页面的“诊断”中说明（todo：这个还没有完全实现），

NoteManager支持如下额外的role：

####  dtag

这个role用于写文档的查询关键字，比如：
```rst
:dtag:`Linux, 内核, 文件系统`
```

- 可以写在正文任意位置；
- 多个标签用逗号分隔；
- 标签本身会从渲染正文中移除，只作为元数据。

dtag和index（默认支持的role）都会被作为文档的索引使用。

#### ref

这是rst文件默认支持的role，但NoteManager进行了扩展，你可以直接引用某个标签，比
如：
```rst
:ref:`my-label`
```
或：
```rst
:ref:`目标章节 <my-label>`。
```

大部分工具不允许你的标记冲突的，但NoteManager会在网页上动态解释这个标记，所以
冲突是没有问题的。被引用位置写法是标准语法：

```rst
.. _my-label:

目标章节
--------
章节具体内容
```

rst的索引也可以索引md文件中的标记。

#### doc

NoteManager的doc role可以同时用于引用md或者rst文件，不需要专门指定，比如：
```rst
:doc:`path/to/doc`
```
这个doc不需要写明是doc.md，doc.txt，还是doc.rst，NoteManager会自动判断。

### 1.2 扩展directive

directive类似role，只是常常用于多行的情形。不少定义是同时支持role和directive两
种形态的。directive这样定义：

```rst
  .. directive:: 参数
    更多参数
```

NoteManager对directive采用role类似的处理策略。我们支持如下扩展directive：

#### toctree

NoteManager支持类似Sphinx的toctree语法：

```rst
.. toctree::
   :maxdepth: 2
   :caption: 目录

   foo
   bar
```

注意：这是**简化列表**，不是完整 Sphinx toctree：

- 不会自动展开子目录；
- 不会生成 Sphinx 的隐式文档树；
- 条目会生成指向文档的链接；
- 不要依赖 Sphinx 的 `glob` / `hidden` 等完整行为。

普通文档链接仍然是更可靠的方式。

#### cnote

cnote类似node directive，但属于NoteManager专门处理的提示格式。类似：

```rst
.. cnote:: 注意

   这里是提示内容。
```

渲染为带标题的提示块。

#### centered

这个扩展用于显示剧中显示的内容，例如：

```rst
.. centered::

   居中显示的内容。
```


## 2. Markdown

NoteManager对于Markdown文件启用如下标准插件：

- `fenced_code`
- `codehilite`
- `tables`
- `toc`
- `md_in_html`

因此支持：

- 围栏代码块；
- 代码高亮；
- 表格；
- 标题自动生成 TOC；
- Markdown 中嵌入简单 HTML。

不启用 YAML front matter、脚注、任务列表等额外扩展。**不要使用 YAML
frontmatter 代替 dtag**；请使用正文中的 `#tag` 或 reST 的 `:dtag:`。（todo：为
什么不使用YAML？待改进）

和rst一样，md我们默认支持数学公式和Mermaid，支持中文段内换行。

### 2.1 dtag扩展

NoteManager处理Markdown的时候，用#xxx表示dtag，比如：

```markdown
这是正文。#Linux #内核 #文件系统
```

规则：

- `#` 必须出现在行首、空白或常见中英文标点之后；
- 支持中文、字母、数字、下划线，以及 `/ + _ . -`；
- `# 标题` 是标题，不是标签；
- `[](#anchor)` 中的 `#` 不是标签；
- 建议不要依赖代码块里的 `#tag`。

示例：

```markdown
# 不是标签，这是 Markdown 标题

这是正文 #数学 #概率论
```

todo: 这么复杂，为什么不直接用yaml方式定义？


### 2.2 链接

Markdown的默认链接语法，比如：
```markdown
参见 [io_uring](../Linux内核/io_uring.md)。
```
不但可以引用md文件，还可以引用其他笔记文件。（和rst不同，rst语法天然不需要写扩
展名，所以会自动判断，md语法就是要写扩展名的，所以是确指。）

Markdown文件不能定义额外的锚点，只能引用特定的章节（例如 `#section`）。

## 3. 简单文本文件扩展

既然用户写成文本文件，我们就认为你不想做过多的渲染，这种文件尽量原样渲染：分行
就直接分行（todo：现在不是，待修改），空行就直接是空行，内容完全和原来的样子一
致。

但我们仍加上有限的语言要素：

* “nMr:”开头（大小写敏感）的行作为注释自动忽略，内容自动写入诊断信息（todo：待
  实现）

* 注释中如果出现#xxx#的pattern，中间的xxx统一作为dtag（dtag的含义见reST的相关
  部分）关键字处理，xxx和reST一样，可以用逗号分割多个关键字。
